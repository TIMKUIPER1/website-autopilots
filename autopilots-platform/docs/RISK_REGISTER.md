# Risk Register

| Risk | Impact | Current control | Owner / next action |
| --- | --- | --- | --- |
| Demo mistaken for production | Critical | Persistent demo labels; no external writes | Product: retain environment badges |
| Cross-tenant access | Critical | Server organization checks plus PostgreSQL RLS in the local foundation | Engineering: execute adversarial RLS tests against a disposable Supabase sandbox |
| Credential leakage | Critical | Raw demo secrets discarded | Security: managed vault and rotation |
| Incorrect financial truth | High | Demo cost quality label; no margin claims | FinOps: provider reconciliation |
| Duplicate/replayed effects | High | Tenant-scoped durable idempotency contract in the local foundation | Platform: validate concurrent requests in sandbox |
| Stale human approval | High | Context version and R3 approval are created transactionally | Platform: add execution-time row locking before enabling commands |
| In-memory product-state loss | High | Identity sessions are now durable; demo product workflows remain explicitly in memory | Platform: migrate portfolio reads and governed commands after sandbox acceptance |
| Provider outage/rate limit | High | Bounded read-only probes, stable safe error codes and explicit degraded/unavailable states | Integrations: add timeout budgets, backoff and alert deduplication before continuous polling |
| Overbroad agent autonomy | High | Server allowlist, risk policy, kill switch | AI Ops: evals and earned autonomy |
| Legal evidence incomplete | High | Version/hash fixture only | Legal: approve documents/retention |
| Operating-brand metrics mistaken for live | Critical | Demo environment, source quality and unavailable values shown explicitly | Data: require successful sync and reconciliation before promotion |
| Brand/customer identifier collision | Critical | Immutable prefixed IDs and server membership checks | Data: preserve IDs in PostgreSQL migration |
| Missing AutoReviews mappings | High | Four external sources fail closed as blocked | Integrations: configure sandbox IDs and reconciliation |
| Control plane becomes a product-data monolith | High | Product-owned data planes and a versioned snapshot contract | Architecture: reject raw operational-table replication |
| AI links the wrong external resource | Critical | AI mappings remain proposals with confidence and evidence | Operator must approve mappings before promotion |
| Migration targets the wrong Supabase project | Critical | The runner accepts only project `wurycoodzcybaxcgqxps`, derives it from direct hosts or pooler usernames before connecting, and still requires explicit permission/change ID; CI verifies immutable applied checksums | Operations: keep automated deployment absent until backup/restore and environment promotion are separately authorized |
| Legacy `public` tables lack RLS | Critical | New OS schemas are isolated and fully RLS-protected; legacy tables were not changed during foundation deployment | Engineering: inventory all 18 Advisor findings and stage compatible policies before any legacy exposure or cutover |
| Supabase token leaks into application storage or logs | Critical | Provider tokens exist only during the MFA callback; the application stores only a SHA-256 hash of its own 256-bit cookie | Security: add automated log-redaction tests before production |
| Owner operates at AAL1 before MFA setup | Critical | The managed callback creates no Autopilots session until TOTP enrollment or challenge returns an AAL2 token | Identity: owner completes enrollment from the delivered login link; add a second recovery factor later |
| Stale access after role or membership revocation | Critical | Every cookie resolution rejoins active profile and membership state; logout writes revocation and audit evidence | Identity: add live suspension/revocation tests with a disposable second user |
| Health endpoint exposes upstream internals | High | Adapter returns a versioned allowlisted contract and strips private upstream error details | Security: retain response-bound and disclosure tests for each new connector |
| A reachable endpoint is mistaken for production readiness | Critical | UI distinguishes healthy, degraded and unavailable and labels every probe `live_readonly_probe`; provider writes remain false | Operations: require dependency, reconciliation and human promotion gates before production status |
| Polling creates duplicate alert noise | High | Observation keys are idempotent and one partial unique index deduplicates each active brand/connector/error incident | Operations: add bounded polling cadence and notification suppression windows |
| Operator acknowledges stale incident context | High | R1 acknowledgement locks the incident and requires the current occurrence count as context version | Runtime: surface refresh-required errors and never auto-retry an acknowledgement with changed context |
| Business conflict is mistaken for retryable database failure | High | Stale incident context uses explicit `P0001`; runtime maps the exact message to HTTP 409 and acceptance verifies bounded response time | Engineering: reserve and document application SQLSTATE/message pairs before adding new commands |
| Health page view silently mutates evidence | High | All GET health and incident routes are side-effect free; persistence is an explicit JSON POST with an idempotency key and MFA | Security: retain route-order and no-write acceptance checks |
| Multiple runtime instances duplicate scheduled probes | High | A unique database lease per scheduler key/time bucket elects one holder; heartbeat, bounded expiry recovery and observation idempotency add independent controls | Platform: add multi-instance load and lease-expiry chaos acceptance before production hosting |
| Monitoring silently becomes stale after a runtime outage | High | Service-role freshness snapshot labels every brand fresh, stale or never observed against a bounded threshold | Operations: add notification suppression and escalation delivery after the provider channel is explicitly authorized |
| Scheduler impersonates a human owner | Critical | Monitoring v2 requires the non-login service principal `autopilots:health-monitor`; the owner profile is rejected by the machine RPC and legacy human lease RPCs are revoked | IAM: move the server transport credential into the approved production vault before hosting |
| Machine identity gains broad platform authority | Critical | Service-principal scopes use an allowlist, legal-entity/brand foreign keys, active status and hard database checks that login and external writes remain false | Security: add separate principals per future workload and never reuse the monitor for provider activation |
| Access request accidentally becomes a real invitation | Critical | Staging stores an R2 command and pending approval only; database checks force provider invitation and external-write flags false | IAM: require separate explicit authority and a new reviewed executor before any invitation transport exists |
| Privilege escalation through an owner grant | Critical | The staged role allowlist excludes `owner`; only legal-entity-wide owner/admin memberships may stage other roles | IAM: define a break-glass, dual-control owner-transfer procedure before implementing owner changes |
| Stale or replayed access decision | Critical | Approval/rejection locks the request, requires its current context version, creates a separate idempotent R2 decision command and rejects divergent reuse | Identity: retain the same context lock when a separately authorized membership apply step is designed |
| Approved intent mistaken for active access | Critical | Decision evidence explicitly records `membershipApplied=false`, `providerInviteSent=false` and `externalWrites=false`; the roster keeps status separate from active memberships | Product: keep approved requests visibly blocked until a separately authorized apply workflow exists |
| Deployed migration history is silently rewritten | Critical | The platform gate pins all 14 applied filenames and SHA-256 checksums, requires transaction wrappers and rejects unregistered files | Database: correct defects only through a separately reviewed immutable migration |
| Repository credential is committed | Critical | The platform gate scans every tracked platform file for live Stripe/Supabase keys, assigned service-role credentials and private-key blocks | Security: expand allowlisted detectors with each new provider and use a managed vault before hosting |
| Connector configuration exfiltrates a secret or probes an internal service | Critical | Remote destinations require HTTPS and an exact separate allowed origin; credentials/query/fragment URLs fail before fetch; loopback HTTP is local-only and responses are bounded | Integrations: add DNS/IP resolution pinning at the production egress proxy before remote hosting |
