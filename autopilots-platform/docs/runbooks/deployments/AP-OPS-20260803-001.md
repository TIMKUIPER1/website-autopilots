## Boundary

Health observations receive a bounded idempotency key. A partial unique index
prevents duplicate observation evidence, while a second partial unique index
keeps at most one active incident for each brand, product connection and stable
error code. A new observation increments `occurrence_count`, which is also the
incident context version. A healthy observation resolves active incidents for
that connection.

`public.autopilots_record_product_health(...)` accepts only recent observations,
stable safe error codes, bounded summaries, an active owner/admin/operator and
a registered sandbox product connector. It appends an R0 audit event and never
enables provider writes.

`public.autopilots_acknowledge_incident(...)` locks the incident, requires its
current context version and writes one idempotent R1 command, one zero-cost
usage entry and one audit event. It does not remediate or call the product.
