## Reason and boundary

The first read model correctly exposed durable runs, but its `attention24h`
summary counted only partial or failed scheduler executions. A run may execute
successfully while its product counts still contain degraded, unavailable or
failed products. Presenting that as zero attention would be misleading.

This immutable forward correction replaces only the stable read function. It
separates `schedulerSucceeded24h`, `runFailures24h` and `attention24h`, where
the final value also counts non-healthy product signals. Organization scope,
the 20-run limit, omitted holder IDs and all no-effect flags remain unchanged.
