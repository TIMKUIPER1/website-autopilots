## Authorization boundary

The organization roster is read through a service-role RPC that rechecks an
active, legal-entity-wide owner, admin or auditor membership. Owners and admins
may stage a request for `admin`, `operator`, `finance`, `auditor` or `viewer`.
The initial contract deliberately cannot grant `owner`, create an Auth user,
create a membership, send an invitation or call an external provider.

Each staged request transaction creates exactly one access-request row, an R2
workflow command in `approval_required`, a pending R2 approval, an append-only
zero-cost usage entry and an audit event. A tenant-scoped idempotency key returns
the original contract on an identical replay and rejects a divergent payload.

The initial roster query referenced a non-existent legal-entity field and
failed closed during live verification, before any access write. The deployed
migration was not edited. `AP-IAM-20260803-006` immutably corrected the metadata
fallback to `legal_name`, preserving registered migration history.
