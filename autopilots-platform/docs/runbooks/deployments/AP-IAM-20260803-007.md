## Decision boundary

Only an active legal-entity-wide owner or admin may approve or reject a staged
request. The RPC locks the request, original command and pending approval and
requires the exact current context version. It closes those records, then adds
an idempotent `iam.access.decide` R2 command, zero-cost usage entry and audit
event. Identical replay returns the original evidence; divergent reuse fails.

Approval is intent, not activation. Both outcomes return and record
`membershipApplied=false`, `providerInviteSent=false` and
`externalWrites=false`. No Auth user or IAM membership is created.

The first live acceptance exposed that the audit result allowlist lacked the
explicit value `approved`. The whole fixture rolled back. The registered
decision migration was preserved, and `AP-IAM-20260803-008` added and validated
the bounded audit value in a separate immutable migration.
