# AP-OPS-20260803-012 — Connector configuration posture

- Implemented: 2026-08-03
- Runtime: local managed sandbox at `127.0.0.1:4310`
- Database migration: none
- Change ID: `AP-OPS-20260803-012`
- Provider authorization and external writes: disabled

## Boundary

The portfolio can now show where each authorized product connector obtains its
runtime configuration without returning an endpoint, allowed origin or secret.
The server contract exposes only bounded categories:

- configuration source: platform runtime, sandbox default or environment;
- destination class: internal runtime, loopback, remote HTTPS or blocked;
- origin state: configured, not configured, invalid/mismatched or not required;
- credential state: configured, not configured or not required.

The route requires an internal server session and derives the product list from
that session's brand scope. Unknown or duplicate slugs are excluded. There is
no POST route, provider executor or configuration editor.

## Acceptance

The complete platform gate passed 278/278 tests. Contract tests proved that a
remote URL, allowed origin and sample credential never occur in the serialized
response. An unsafe remote HTTP destination failed closed without exposing its
hostname. Anonymous access to the managed route returned HTTP 401.

A separate local visual testsession rendered the panel for all four products:

| Product | Configuration source | Destination | Credential state |
| --- | --- | --- | --- |
| Autopilots | platform runtime | internal | not required |
| AutoReviews | sandbox default | loopback | not configured |
| AutoPlanner | sandbox default | loopback | not required |
| RoofPlanner | sandbox default | loopback | not required |

The panel explicitly says that configuration evidence is not health or
production-readiness evidence. Endpoint and credential values are never shown;
provider authorization and external writes remain false. The separate visual
test runtime was stopped after acceptance, while the managed sandbox remained
active.

## Recovery

Stop the local runtime or revert the application commit. No Supabase schema or
provider state changed, so database rollback is unnecessary. Preserve the
presence-only contract if the panel is moved or restyled.
