## Boundary

The scheduler runs the same versioned read-only product probes as the manual
route. It uses one deterministic idempotency key per time bucket and operating
brand. A second run in the same bucket replays the existing evidence; an
overlapping in-process run returns `overlap_blocked`.

The configured authority profile supplies current membership scope only. The
health function writes the actor and source as the system monitor, so the owner
is not represented as having manually performed or acknowledged anything.
Private provider failures become only `MONITORING_CAPTURE_FAILED` in scheduler
state. No automatic remediation or acknowledgement exists.

## Current limitation

The scheduler lease is process-local. Deterministic database idempotency makes
duplicate evidence safe, but production multi-instance hosting still requires
a durable database lease, missed-run recovery, freshness SLO and notification
suppression policy. Keep this runtime in one local instance until those controls
exist.

## Recovery

Set `MONITORING_SCHEDULER_ENABLED=false` and restart the runtime. Existing
incident and audit evidence remains append-only. Manual read-only health and
explicit capture routes continue to work.
