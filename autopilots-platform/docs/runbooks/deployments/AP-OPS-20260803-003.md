## Boundary

The scheduler runs the same versioned read-only product probes as the manual
route. It uses one deterministic idempotency key per time bucket and operating
brand. A second run in the same bucket replays the existing evidence; an
overlapping in-process run returns `overlap_blocked`.

The initial authority profile supplied membership scope only. Since
`AP-IAM-20260803-004`, monitoring v2 uses the dedicated non-login
`autopilots:health-monitor` service principal and rejects human profiles from
the lease contract. Private provider failures become only
`MONITORING_CAPTURE_FAILED` in scheduler state. No automatic remediation or
acknowledgement exists.

## Superseded limitation

The process-local lease limitation was removed by `AP-OPS-20260803-004`.
Deterministic observation keys remain a second idempotency boundary. Provider
notification delivery and production-vault transport credentials are still
separate production gates.

## Recovery

Set `MONITORING_SCHEDULER_ENABLED=false` and restart the runtime. Existing
incident and audit evidence remains append-only. Manual read-only health and
explicit capture routes continue to work.
