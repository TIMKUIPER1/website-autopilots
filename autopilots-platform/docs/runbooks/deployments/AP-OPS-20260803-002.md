## Runtime boundary

Incident reads are allowlisted snapshots produced by
`public.autopilots_incident_snapshot(profile_id, brand_slug)`. The function
rechecks the active profile and current legal-entity/brand membership and
returns no private incident context. `anon` and `authenticated` cannot execute
it; only the server role can.

Ordinary health and incident GET requests remain side-effect free. Persistence
requires an explicit JSON POST, a valid server session, internal role, current
brand scope, MFA and an idempotency key. The product probe remains read-only.
Acknowledgement is a separate R1 POST with the current incident context version.
Neither route performs remediation or product writes.
